# GameFleet – guide for AI assistants and contributors

GameFleet is a small self-hosted dashboard for game servers: a FastAPI backend queries each server with its
native protocol and a SvelteKit SPA shows status, players and per-game details. Read this file before changing
anything; keep it current when the architecture or the rules below change.

## Architecture

```
backend/src/gamefleet_backend/
  main.py                 FastAPI app; version comes from pyproject.toml via importlib.metadata
  api/                    routers: servers (CRUD + live info), games (cached artwork), docker
  services/               live_server_info (fan-out per protocol), game_asset (artwork cache), docker
  lib/query/<protocol>.py one module per protocol: steam (A2S), minecraft, factorio (RCON), satisfactory, ark_ase, ark_asa (EOS)
  models/game_server_type.py  GameServerType enum + GAME_CATALOG (GameSpec: protocol, default ports, query-port rule, label)
  models/server_info.py   live-info models: discriminated union on `kind` (base/steam/minecraft/factorio/satisfactory/ark)
  db/session.py           engine, init_db(): create_all + idempotent LEGACY_SCHEMA_UPGRADES (this IS the migration system)
  db/models/game_server.py  GameServer table + GameServerPublic API model
frontend/src/
  lib/api/Api.ts          GENERATED by `make swagger` (swagger-typescript-api) – never edit by hand
  lib/api/types.ts        LiveServerInfo derived from the generated client
  lib/live.svelte.ts      live-info store, refreshed every 30 s, cached in sessionStorage across navigation
  lib/games.ts            display labels / artwork URLs per game
  lib/components/         UI components; routes/main (dashboard), routes/server/[id] (detail)
  app.css                 Tailwind v4 (CSS-first: @import 'tailwindcss', @custom-variant dark, design tokens). No tailwind.config.js.
```

Key decisions (do not undo without a reason):

- **Schema changes go into `LEGACY_SCHEMA_UPGRADES`** as idempotent SQL. Alembic is configured but has no versions and is
  not run anywhere; do not add migrations. The `game` column is `VARCHAR(50)`, not a Postgres enum, so new game types need no DB change.
- **`GameServerPublic.from_server` validates from attributes** because table rows hold `game` as text; passing
  `model_dump()` output caused Pydantic serializer warnings.
- **Live info is a discriminated union on `kind`.** New game-specific fields go into a `*ServerInfo` subclass; the frontend
  narrows on `kind`.
- **Frontend is a static SPA** (`adapter-static`, `fallback: index.html`). Links use `resolve()` from `$app/paths`.
- **Backend container uses host networking** so it can reach LAN game servers and any local Postgres.
- Prettier is intentionally not applied repo-wide. Do not reformat files you are not otherwise changing.

## Adding a game

1. Add the enum value and a `GameSpec` to `GAME_CATALOG` in `models/game_server_type.py`.
2. Steam games: add the app id to `STEAM_APP_IDS` in `services/game_asset_service.py` (artwork). Others: explicit image URLs there.
3. Non-A2S games: add `lib/query/<game>.py` returning one of the `*ServerInfo` models and wire it in `live_server_info_service.py`.
4. Add the label in `frontend/src/lib/games.ts`, run `make swagger`, commit the regenerated `Api.ts`.

## Versioning and commits

- The project has **one version**, kept identical in `backend/pyproject.toml` and `frontend/package.json` (currently 0.5.0).
  The API reports it, `make release` tags images with it.
- **Bump the version in the same commit as the change** when the commit is user-visible:
  patch (0.5.x) for fixes and dependency updates, minor (0.x.0) for features or UI changes, major for breaking API/DB changes.
  Pure docs/tooling commits do not need a bump.
- After changing `pyproject.toml` run `cd backend && uv lock` and commit `uv.lock`; after changing `package.json` commit `pnpm-lock.yaml`.
- Commit messages: imperative, one line summary (see `git log`), body only when the why is not obvious.
- Never commit `.env`, `backend/data/`, `build/` or generated caches (see `.gitignore`).

## Verifying changes

```bash
make check            # svelte-check + eslint + backend import check
cd frontend && pnpm build
make up               # or: VERSION=x docker compose build   (base images, lockfiles)
```

Backend smoke test on a spare port: `cd backend && uv run uvicorn gamefleet_backend.main:app --port 8010`, then
`GET /api/servers` and `/api/servers/live-info`. The dev database is the `gamefleet-postgres-dev` container (`db-dev/`).

Headless screenshots: `brave --headless=new --disable-gpu --no-sandbox --hide-scrollbars --window-size=1440,1100
--virtual-time-budget=60000 --screenshot=out.png "http://localhost:3000/main?theme=light"` (`?theme=` is a deliberate override in `app.html`).

## Findings from protocol testing

- Public Minecraft (gommehd.net), Bedrock (geo.hivebedrock.network), 7 Days to Die, TF2 and Garry's Mod servers answer their
  queries; a local `factoriotools/factorio:stable` container (`gf-factorio`, RCON password in `/factorio/config/rconpw`) covers Factorio.
- ARK: SA official/Nitrado servers are resolved through ARK's CDN server lists plus the EOS `sessions/{id}` endpoint
  (the older `matchmaking/filter` call returns 403). Private ASA servers need RCON. Official ASE hosts do not answer A2S.
- Satisfactory could not be verified: the known public API server is down and `steamcmd +login anonymous` can no longer
  download the dedicated server. The module runs with `skip_ssl_verification=True` and is untested against a live server.
- BattleMetrics needs a paid API plan and the Steam master server hostname no longer resolves; do not build on either.

## Working rules for AI assistants

- Read the relevant module before editing; keep diffs focused on the request and do not touch unrelated formatting.
- Run `make check` (and `pnpm build` for frontend changes) before declaring work done; report failures verbatim.
- Regenerate and commit `Api.ts` whenever backend API models change.
- Prefer editing `LEGACY_SCHEMA_UPGRADES`, `GAME_CATALOG` and existing components over introducing new layers.
- Ask before anything destructive (dropping volumes, `git push --force`, deleting data) and before pushing images.
- Never put secrets in code, compose files or this document; RCON passwords stay in the database and `.env`.
- Update this file and the README when you change architecture, tooling versions or the make targets.
